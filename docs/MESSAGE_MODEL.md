# Saved message model

The canonical types are [Message and MessageContent](../lib/domain.ts). Passage uses Responses-style `type`, `role`, ordered `content`, and optional assistant `phase`; these saved records are not directly replayable API inputs.

- Preserve message identity, original roles, content order, block boundaries, and Markdown. Assistant text uses `output_text`; other roles use `input_text`.
- Retain `commentary` or `final_answer` only when the source supplies it. Do not infer a phase from message position.
- `kind: 'reasoning_summary'` identifies an assistant summary explicitly exposed by the public source. Codex v3 captures preserve this distinction; the original text stays in `output_text`. This optional JSON field needs no database schema migration.
- The local `tool` role preserves visible tool contributions. Typed `omitted` blocks distinguish known missing or unsupported content from original conversation text; they do not claim the media itself was captured.
- `image` blocks retain captured raster images with a SHA-256 hash, internal R2 key and dimensions. Markdown image destinations use `passage-image:<hash>` with matching saved metadata in `message.images`. Original alt text and extracted summary text are preserved. Audio, video, files and interactive artifacts remain omissions.

[Message projections](../lib/messages.ts) derive reader Markdown with omission labels (`messageMarkdown`) and summary input containing only extracted text (`messageText`). Neither projection is stored as another copy of the message.

[Reader groups](../lib/reader.ts) fold consecutive reasoning summaries, commentary, and tool entries into closed “Reasoning & activity” disclosures. User messages and answers remain visible, and all saved content and message anchors retain their order. The answer jump uses the visible messages. The header shows the saved date without a message count or a provider introduction row. Copying a passage confirms success inside the button without adding a status line; clipboard failures still offer a manual-copy link. Markdown and syntax highlighting run on the server; small client controls handle copying, table width, and long-question expansion.

For Codex user messages, the reader presents a complete `codex_delegation` envelope as its input with a “Sent from another task” note, matching the public source. The original envelope remains stored; ordinary and malformed HTML stays escaped and visible. Local file references keep their labels and gain an unavailable-file glyph, without navigation or downloads. Captured images render lazily from the passage's same-origin media route with their intrinsic dimensions. Image-bearing tool entries remain visible in the main conversation. Uncaptured and unrecognized image references retain explicit omission labels and an image placeholder; arbitrary remote images in saved text never load directly.

Inline images are capped at 400px on desktop and fill the conversation width on mobile (600px and below). Captured images open a lightweight modal lightbox when clicked or activated with the keyboard; its preview fits the viewport without the inline 400px cap. The image animates from its inline position, reusing the decoded image while the full preview loads; reduced-motion preferences skip the zoom animation. Clicking the enlarged image, the backdrop or Close, or pressing Escape closes it. A download button uses the same publication-bound media route. The lightbox reuses the personal-site implementation and does not change saved snapshots or image access rules.

Media delivery looks up the available publication and serves only image hashes referenced by its snapshot. R2 stays private, and bytes are hash-verified before streaming. Streaming accommodates supported images larger than Vercel's buffered response limit ([Vercel delivery guidance](https://vercel.com/kb/guide/how-to-bypass-vercel-body-size-limit-serverless-functions)). Responses require revalidation and use private caching so disabled passages cannot expose media through fresh CDN responses. As with other saved content, browser/platform copies already received cannot be recalled.

Complete Codex `send_user_message_question_reply` envelopes are also a reader-only presentation case. The selected answer is shown as a compact “Prompt answered” response while the provider envelope remains unchanged in the saved snapshot. Passage accepts both well-formed JSON and the observed Codex variant whose `questionItemId` is not escaped correctly; incomplete or ambiguous envelopes stay escaped and visible.

Complete numeric `:codex-annotation{index="…"}` pragmas in Codex assistant messages are source presentation metadata rather than prose. The reader hides these exact directives while preserving them in the saved snapshot; malformed pragmas and the same text outside Codex assistant messages remain visible.

Older Codex v1/v2 captures flattened reasoning into unphased assistant messages. Their reader-only compatibility rule uses the stable `codex-<turn>-<item>` identities to retain every explicit final and the last unphased assistant contribution per turn (unless followed by an explicit final), folding earlier contributions as activity. This is a reversible presentation heuristic, not a recovered source classification. Ordinary ChatGPT/Claude messages and new Codex captures never use that heuristic. Existing snapshots, saved phases, and summary-generation inputs are unchanged.

[Migration 0004](../drizzle/0004_responses_message_content.sql) wraps older Markdown in text blocks while preserving identity, roles, and order. Historical omission labels already flattened into Markdown stay verbatim; structured omission metadata is available only from new captures.

ChatGPT v4 imports preserve exposed citation destinations as Markdown links, enabling the same reader previews as ordinary source links. Follow-up actions link back to the original chat and retain the provider’s full prompt in the Markdown link title, which the reader preserves. These links do not automatically submit a follow-up. Existing snapshots are immutable; reimport the provider URL to capture previously discarded reference metadata.

## Reader link previews

Published readers enhance HTTP(S) links inside saved chat text with a compact preview on mouse hover (220 ms dwell) or keyboard focus. Escape, scrolling, blur, and navigation dismiss it; link destinations and native navigation remain unchanged. This enhancement is mounted only around the published conversation, not marketing examples or other site links.

The idle scheduler warms all eligible external links in the saved chat, including offscreen and collapsed content. After page load and 150 ms of input quiet, CPU idle callbacks start up to four concurrent requests. Each destination's metadata is followed promptly by its social image and favicon (loaded and decoded sequentially in that destination's slot), rather than waiting for every page's metadata first. Duplicate URLs share work, and scrolling does not discard offscreen previews. Removed sources, page disposal, hidden tabs, offline, Save-Data, and 2g connections cancel or pause speculation. Completed attempts are retained for the mounted conversation, with no viewport limit or recurring polling.

Client and server caches allow eight concurrent jobs, at most four background jobs, and retain up to 512 entries (10-minute success / 30-second failure TTL). Hover joins and promotes shared speculative jobs; background requests use low-priority hints. Browser image caching is reused on hover. Cache lifetime is per browser bundle or server process, with no database persistence.

The same-origin JSON endpoint parses inert Open Graph/Twitter/title metadata. It validates public DNS and pins sockets on every HTTP or immediate HTML redirect, forbids credentials, unusual ports and HTTPS downgrades, and bounds acquisition to five seconds, five redirects and 512 KiB of HTML. Repaint's conservative query policy strips tracking and retains known content IDs/locales; unknown queries use the original link without a preview. Unavailable pages fall back to link text and domain.

Preview artwork and declared favicons use direct HTTPS image URLs with `no-referrer`, outside the Next.js image optimizer. Browser image caching is reused by idle preloads and hover; failed artwork leaves the text card. Destination HTML is never rendered or executed. These optional link metadata images are separate from the saved conversation's omitted media.

Known platform URL formats can override extracted metadata before the generic first-image selection. YouTube watch, short, live, embed, legacy embed, privacy-enhanced embed, and `youtu.be` video links derive the video's stable high-quality thumbnail from its validated 11-character ID, so a page's missing or unsuitable Open Graph image does not remove the poster.
